# 中文学习版：翻译与词卡质量规则

日期：2026-10-21；状态：评审稿，尚未执行全量翻译。

## 三种内容明确分开

1. **译文**：忠实表达原文，不增加结论，不省略前提。
2. **学习注释**：帮助初学者理解的比方、例子与术语解释，不冒充原作者观点。
3. **技术勘误**：原文可能不准确的地方，列出原句、说明、适用条件和依据。

例如，不能把“可能改善延迟”翻译为“一定降低延迟”；不能把特定硬件上的实验结果翻译为所有环境下的性能保证。

## 已发现的原文疑点样本

位置：`docs/inference/caching.md` 的“KV Cache Offloading and Storage Hierarchy”开头。

原句：

> As LLM context windows continue to expand, KV cache storage requirements grow exponentially.

忠实译文：

> 随着大语言模型的上下文窗口不断扩大，KV 缓存的存储需求呈指数增长。

应单列的技术说明：

> 原文这里的“指数增长”不适合作为通常 KV 缓存容量的数学描述。对于模型结构、批量大小和数据精度固定的常规全注意力模型，KV 缓存的存储量通常随实际缓存的 token 数近似线性增加。也就是说，在其他条件不变时，缓存的 token 数翻倍，所需容量大致翻倍，而不是指数式膨胀。静态缓存可能按预设长度预分配；滑动窗口等机制还会改变实际增长方式。不要把 KV 缓存容量与注意力计算的复杂度混为一谈。

依据：Hugging Face Transformers 官方文档明确说明键值张量包含序列长度维度，动态缓存随新 token 增长，并指出 memory grows linearly；同页也区分静态与滑动窗口缓存。

来源：https://huggingface.co/docs/transformers/cache_explanation

## 每篇翻译的检查表

- 记录原文件路径、原文版本、译文状态和审校日期。
- 逐段对应，不以摘要替代正文。
- 检查否定、条件、程度、时态与能力状态。
- 数字、单位、版本号、硬件配置和性能测试条件保持一致。
- 保留命令、API、配置键、项目名和链接目标。
- 检查表格行列、图片、公式、脚注与交叉引用。
- 首次出现的缩写展开，不把不同概念错误合并。
- 发现过时或可疑说法时加独立说明，不偷偷改原意。
- 原文更新后标记需要重新复核，不能继续显示“已同步”。

## 词卡字段约定

### 技术术语

- 名称、别名与缩写全称。
- 中文名称。
- 一句话日常语言解释。
- 本文具体含义与文章关联。
- 最小例子，必要时说明比方不成立的边界。
- 容易混淆的词。
- 事实依据链接及检查日期。

### 英语单词

- 词形、词性、英/美音标及依据。
- 单词本来的常见意思。
- 在当前句子中的意思。
- 英文原句和对应中文。
- 发音方式与可用状态：系统合成语音须明确标识。

### 共同规则

- 不用中文谐音替代音标。
- 不把专有名词强行逐字翻译。
- 不给没有查证的读法伪造音标。
- 不把一个词的释义机械套到所有文章。
- 未收录时显示“暂未收录”，而不是随机猜释义。
