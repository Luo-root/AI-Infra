# AI-Infra 中文学习版：需求评审稿

日期：2026-10-21

上游：https://github.com/pacoxu/AI-Infra

本地基线：`3cc83ef18ed502929e55d0e598129c7525e5f993`

## 目标与当前事实

为 AI-Infra 方向的初学者建立一套可持续学习的中文文档网页：准确翻译、按需查术语、按需学英语，电脑和手机都能读。

当前目录最初为空，现已克隆原仓库。原仓库有 145 个受版本控制的 Markdown 文件，已有中文首页和部分中文文章，但不能据此认定所有正文已翻译。当前没有 package.json，也没有现成学习网站工程。原仓库采用 Apache-2.0 许可证；衍生版本需保留许可证及适用声明，明确标识修改内容。

本轮为多项功能的立项与资料核查阶段。下面各票评审通过后，再开始改正文、翻译与网站实现。此文件不是已完成声明。

## 票 1：筛选 Issue/PR 并补充教材

### 谁会用

希望少走弯路、不被过时资料和未经验证的设想误导的学习者。

### 要防止哪类错误

- 把已合并 PR 再应用一次。
- 把关闭 Issue 当作内容一定落地，或把开放 Issue 当作内容一定有用。
- 把未完成的实验计划、旧版本状态和产品宣传写成确定事实。

### 已核实事实

检索到 175 个 Issue、233 个 PR；开放 PR 为 6 个。完整分类另见本轮核查报告。统计是本轮快照，不代表后续数量不变。

### 实现倾向

逐项保留来源链接、筛选理由、状态和本地落点。分类为“核心学习内容、进阶专题、资料入口、维护/重复/历史、待验证设想”。有意义不等于立即加入入门正文；也不等于其技术主张已经独立验证。

已在 main 中的内容只建立学习索引，不重复合入；未收录内容先核对官方依据，再以标明来源的增补加入本地学习版。保留原有英文，新增内容与译文明确区分。

### 验收标准

- 全部 Issue/PR 都有可追踪条目，开放条目逐项解释。
- 更新内容可追溯到来源及适用版本。
- 未验证设想不进入“已证实知识”正文。
- 新增图片、相对链接可用。

## 票 2：准确中文翻译

### 谁会用

英语阅读吃力、但需要完整理解原文的学习者。

### 要防止哪类错误

漏译、摘要冒充译文、技术限定词丢失、不同文章同一术语乱译，以及旧译文对应错原文版本。

### 已核实事实

中文首页仍链接大量英文正文。145 篇 Markdown 中，已有 19 组中英对应候选，约 53 篇学习相关文档待翻译或补齐，估算约 8.2 万英文词；已有译文仍须核对完整性与同步状态。详细口径见 `content-inventory.zh-CN.md`。正文中有表格、代码块、HTML 图片、Mermaid 图和相对链接，不能只替换纯文本。

### 实现倾向

不覆盖英文原文；建立明确的中英文配对和源版本记录。默认全量覆盖仓库内的人读文档，按基础、推理、Kubernetes、训练、观测、Agent、案例及历史文章分批交付。许可证保留原文；脚本和配置不作自然语言整段翻译。

忠实保留 may/must、实验条件、版本号、数字、单位、代码和来源。原文有疑点时，不默默改译文：分别展示“原文翻译”和“技术勘误/译者注”，注明依据。已有中文也检查配对与同步状态，不重复生成一份。

### 验收标准

- 翻译清单给出总量、已完成、待翻译、待复核，不能把英文兜底页计作已翻译。
- 标题、段落、列表、表格和注释有对应关系；代码及命令保持可复制。
- 每篇记录来源路径与源版本；原文更新后提示译文可能过期。
- 代表性段落逐句核对限定词、技术含义、数字和单位。

## 票 3：术语与英语词卡

### 谁会用

读到陌生技术词、不想跳出当前文章查词的学习者。

### 要防止哪类错误

把生活中的原义当技术含义；把同一个词在不同语境中的意思混为一谈；用中文谐音误导读音；把机器朗读说成真人标准读音。

### 实现倾向

术语卡包含：英文全称、缩写、中文名称、一句话大白话解释、本文具体含义、最小例子、相关概念和来源。

英语卡包含：词形、词性、音标、英文原义、本文含义、原句与对应中文、发音按钮。英语词与技术词可共用入口，但内容分区。

优先维护本领域词汇和常用技术动词；同时提供选词查询入口，不承诺提前猜到学习者的所有陌生词。查询不到时明确提示未收录，不臆造释义。专名、缩写存在多种读法时说明差异；音标注明英/美音及来源，不能凭空编造。

首版建议使用浏览器系统语音朗读，检测英语语音是否可用；不可用时不显示假成功。系统朗读不保证每台设备发音一致，也不保证离线。固定音频另需核实授权、来源和缓存方式。

### 验收标准

- 多词术语优先于单词匹配，避免把 KV Cache 拆错。
- 不在代码、链接目标、URL 中强行插入词卡按钮。
- 同一词可按文章绑定不同义项，卡片显示当前语境。
- 音标、含义和原句可追溯；未知条目不伪造。

## 票 4：可随时阅读的学习网页

### 谁会用

电脑上系统阅读、手机上碎片学习的同一位用户。

### 要防止哪类错误

正文被密集注释打断、手机没有悬浮操作导致打不开卡片、弹窗遮住内容、链接跳出中文页、离线页面看似可用实际缺资源。

### 实现倾向

建设一个静态学习站：章节导航、全文检索、中英切换、阅读位置保存、主题切换、学习路线、术语入口。

正文默认中文；保留英文阅读/对照入口。术语使用轻量下划线或虚线提示，点击和触摸打开小卡片；长内容在手机用底部卡片展示。支持关闭按钮、点外部关闭、Escape、键盘激活和焦点返回，不只依赖鼠标悬浮。

优先适配电脑与手机；阅读进度先保存在当前浏览器，不暗示跨设备自动同步。提供离线缓存时明确哪些文章、图片和音频已缓存，外部资料不承诺离线可用。

本地预览与公网访问是两件事：本地可读不代表出门能打开。首版建议先完成本地静态站验收，随后由用户决定是否公开部署及目的地。未经单独确认不发布公网、不修改服务器。

### 验收标准

- 桌面、窄屏手机均可阅读，表格与代码不撑破页面。
- 中文文章内链进入中文页；没有译文时显著标识，不冒充译完。
- 检索能定位正文与术语，空结果和未知词有正常提示。
- 词卡可用鼠标、触摸、键盘操作，关闭后恢复阅读位置。
- 构建检查覆盖 Markdown、图片、相对链接、脚注、表格及现有 HTML；根据文档盘点补充实际使用的格式。
- 不把不可信 Markdown/Issue 的原始 HTML 当脚本执行。

## 一次需要确认的事项

1. **推进方式**：建议按以上四票，先交“入门路线 + 一组完整翻译 + 可点词卡”的可用版本，再逐批完成全部文档；最终范围不因此缩减。另一条路是全部翻译完成后才交网站，等待更长，也更晚发现阅读体验问题。
2. **访问范围**：建议先本地验收，再决定公网部署。若需要手机随时访问，需要一个可达的托管地址；局域网本地服务不能代替外网访问。公开部署涉及作品公开及托管选择，需另行确认。
3. **仓库归属**：建议制作用户自己的学习副本并保留上游关联，避免把个性化词卡、译文和学习进度直接当作上游维护任务。尚未创建 Fork、上游 Issue 或 PR；公开写入操作需在目标明确后再执行。

## 当前明确不做

- 不擅自合并上游 PR，也不把所有开放建议一股脑合进正文。
- 不让英文自动回退冒充完整中文翻译。
- 不上传个人数据、学习记录或账号信息。
- 不要求购买 GPU 才能读懂入门内容；需要硬件的实验单独标注条件。
- 不把批量机器翻译等同于逐篇技术复核。
